Problem: One module owns six distinct subsystems behind a single Hono interface. Every change to compaction, token tracking, or import/export touches the same 1575-line file.

Solution: Split into a thin route module that dispatches to a compaction engine, a thread repository, a history store, and a provider-config module — each with its own seam.

locality: compaction bugs concentrate in one module interface shrinks; route becomes dispatch-only each subsystem testable through its own seam delete ~14 inlined SQL statements

Consolidate peak power computation

Worth exploring in-process
packages/shared/src/power.ts — peakPowerFromSeconds (per-second, zero-exclusive)
apps/server/src/routes/strava.ts — computePeakPower (time+watt arrays, zero-inclusive)

Before — three implementations, subtly different

strava: zero-inclusive sum ÷ non-zero count
web: records → per-second → same as shared

same concept, three zero-handling rules

After — one function, adapters convert input

peakPowerFromSeconds (the canonical impl)
strava: streams → per-second
web: records → per-second

one zero-handling rule, testable

Problem: Three implementations of "best average power over N seconds" with subtly different zero/gap handling. A value computed in Strava import can differ from the same activity's web-chart peak — a correctness bug waiting to surface.

Solution: Keep peakPowerFromSeconds as the canonical implementation. Strava and web each provide a thin adapter that converts their input shape to per-second arrays, then delegate.

locality: one zero-handling rule correctness: same peak value everywhere delete 2 duplicate implementations trivially testable with known arrays
Top recommendation

Start with the compaction engine

It's the highest-leverage extract: ~250 LOC of self-contained logic with clear inputs (messages, model, budget constants) and one output (a new thread). It has zero tests today and can't be tested without a running server. Extracting it gives you the first testable seam in the trainer subsystem, proves the pattern for splitting the rest of the god-module, and is small enough to do in one session.
